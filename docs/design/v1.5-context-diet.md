# v1.5 Context Diet — Design

Status: Implemented on branch `feat/v1.5-context-diet` (Parts A and B; release pending) · Scope: v1.5.x (backward compatible) · Owner: OMG maintainers

## 1. Problem

Every Copilot request pays for the context OMG injects before the user's task starts. Measured on `main` (v1.4.4) with `evals/context-baseline.mjs` (o200k tokenizer; MCP tools measured via a live `tools/list` call):

| Category | Count | Tokens | Share |
|---|---:|---:|---:|
| `copilot-instructions.md` (always-on, full text) | 1 | 3,594 | 41% |
| MCP tool definitions (name + description + inputSchema) | 27 | 2,585 | 30% |
| Skill descriptions | 37 | 1,308 | 15% |
| Agent descriptions | 28 | 1,213 | 14% |
| Prompt files | 3 | 38 | 0% |
| **Total always-injected (lower bound)** | | **8,738** | |

This is a lower bound: it excludes host wrapper text around tool lists and anything hooks inject when they fire. Agent and skill bodies (35k + 21k tokens) are loaded on demand and are not part of the problem.

Two sources dominate. The instructions file duplicates what the platform already exposes (agent descriptions, skill descriptions, MCP tool schemas) and the MCP server registers 27 tools, 12 of which no agent or skill ever references.

## 2. Goals and non-goals

Goals
- Cut the always-injected footprint by ≥50% without changing user-visible workflows or breaking existing `OMG: Initialize Workspace` installations.
- Keep every *obligation* (evidence before completion, separate review pass, commit trailers, hook boundaries, graceful degradation) in the always-on file; move *catalogs* and *procedures* to where the platform loads them on demand.
- Make the footprint a tracked metric (`evals/`).

Non-goals (deferred to v2)
- Plugin packaging, hook-driven completion gates (`agentStop`), task-journal redesign, removal of the OMC bridge, OMP runtime compatibility.

## 3. Part A — `copilot-instructions.md` (done in this branch)

Result: 15,459 bytes / 3,594 tokens → 2,097 bytes / **514 tokens** (−86%). Total footprint 8,738 → **5,658** (−35%).

| v1.4.4 section | Disposition | Where it lives now |
|---|---|---|
| Operating Principles, Delegation Rules | Kept, compressed | `## Principles` (routes to executor/debugger/architect/explore/document-specialist retained for deterministic routing) |
| Agent Catalog (28 rows) | Removed | Agent `description` frontmatter — exposed natively by Copilot |
| Skills list (37) | Removed | Skill `description` frontmatter — progressive disclosure |
| Keyword Triggers (25 mappings) | Reduced to 7 | 35/37 skills already carry "Activate when user says…" in their description; 7 short tokens (`autopilot`, `ralph`, `ulw`, `ultragoal`, `ralplan`, `deslop`, `cancel`) stay as hard routes |
| Completion Rules, Verification Protocol | Kept, compressed | `## Completion` — still names `omg_check_completion`, `omg_ultragoal_status`, `omg_checkpoint`, `omg_restore_checkpoint` because tool descriptions say *what* a tool does, not *when* to call it |
| Interactive Hook System (askQuestions rules, per-skill hook table, firing principle) | Reduced to 1 bullet | `## Boundaries`; per-skill question points belong to each `SKILL.md` |
| Commit Protocol (trailers + example) | Obligation kept, format moved | `## Commits` (1 line) → `.github/agents/git-master.agent.md` "OMG Commit Trailers" |
| State Paths, MCP Tools list | Removed | Tool schemas are self-describing |
| Context Pressure & Checkpoint Protocol | Reduced to 1 bullet | `## Completion` |
| External Session Resumption | Removed | Bridge skills remain installed in 1.5 but are deprecated (they have no frontmatter, so they were never natively discoverable) |
| Cancellation | Kept, 1 bullet | `## Boundaries` |

Compatibility
- The H1 `# oh-my-githubcopilot (OMG) - Intelligent Multi-Agent Orchestration` is unchanged. `vscode-omg/src/commands/initialize.ts` uses it as `OMG_MARKER` to find and replace the OMG section inside a user's existing `copilot-instructions.md`, so `OMG: Update Convention Files` upgrades v1.4.x installs in place.
- `vscode-omg/resources/templates/` was regenerated with `npm run sync-templates`.
- `scripts/omg-adopt.{sh,ps1}` copy `.github/` verbatim — no change needed.

## 4. Part B — MCP tool consolidation (implemented in this branch)

### 4.1 Current usage

Only 15 of 27 tools are referenced by any agent or skill:

| Referenced by | Tools |
|---|---|
| `omg-coordinator`, `ralph`, `team`, `omg-autopilot`, `self-improve`, `cancel` | `omg_read_state`, `omg_write_state`, `omg_read_prd`, `omg_update_story`, `omg_verify_story`, `omg_next_phase`, `omg_check_completion` |
| `ultragoal` | `omg_ultragoal_create/status/checkpoint/complete` |
| `push-omc`, `resume-claude` (deprecated) | `omg_checkpoint`, `omg_detect/import/export_external_session`, `omg_compare_checkpoints` |
| **Nothing** (instructions text only, or never) | `omg_clear_state`, `omg_list_active`, `omg_create_prd`, `omg_get_phase_info`, `omg_read/search/write/delete_memory`, `omg_restore_checkpoint`, `omg_context_status`, `omg_select_model` |

### 4.2 Target surface: 6 tools

Unify by *surface* (what is being read or written), not by feature module. One read tool and one write tool over the `.omg/` state tree, one evidence tool, one completion gate, one memory tool, one checkpoint tool.

| New tool | Replaces | Schema sketch |
|---|---|---|
| `omg_read` | `read_state`, `list_active`, `read_prd`, `get_phase_info`, `ultragoal_status`, `context_status`, `restore_checkpoint`, `compare_checkpoints` | `{ scope: "state" \| "prd" \| "phase" \| "ultragoal" \| "checkpoint" \| "all", key?: string }` → returns the JSON for that scope; `all` returns a compact summary (active modes, open stories, active goals, checkpoint age) |
| `omg_write` | `write_state`, `clear_state`, `create_prd`, `update_story`, `next_phase`, `ultragoal_create`, `ultragoal_checkpoint` | `{ scope: "state" \| "prd" \| "story" \| "phase" \| "ultragoal", op: "set" \| "clear" \| "advance", key?: string, value?: object }`; `clear` on `state` replaces `omg_clear_state`; `advance` on `phase` replaces `omg_next_phase` |
| `omg_verify` | `verify_story`, `ultragoal_complete` | `{ target: "story" \| "ultragoal", id: string, evidence: { command: string, output_excerpt: string, passed: boolean }[] }` — **fail-closed**: rejects when `evidence` is empty or any `passed` is false; records verifier + timestamp |
| `omg_check_completion` | unchanged | `{ mode? }` → `{ allow_stop, remaining, message }` as in 1.4, plus additive `complete` (= `allow_stop`), `unverified` (PRD story ids with `passes:false`) and `ultragoal` (active goal or `null`) — the single completion gate; v2 hooks will consult it |
| `omg_checkpoint` | `checkpoint` (write) and `restore_checkpoint` (read, via `omg_read scope:"checkpoint"`) | `{ summary: string, decisions?: string[], modified_files?: string[] }` → also returns `handoff_text`, the skeleton for the next-session prompt required by the 50% session-budget rule |
| `omg_memory` | `read/search/write/delete_memory` | `{ op: "get" \| "search" \| "set" \| "delete", key?: string, query?: string, value?: string, tags?: string[] }` |

Removed outright (no replacement): `omg_select_model` (agents declare `model:` in frontmatter), `omg_detect/import/export_external_session` (OMC bridge — user decision; see §6).

Measured footprint: 6 tools = **863 tokens** (from 2,585; estimate was ~800 — the `$schema` key the SDK emits per tool and the `omg_write` op matrix account for the difference). Total after Part B: 549 + 1,213 + 1,331 + 38 + 863 = **3,994 tokens (−54% vs v1.4.4)**.

### 4.3 Compatibility strategy

- Legacy tool names are **not** registered by default. Setting `OMG_LEGACY_TOOLS=1` on the MCP server (env in `.vscode/mcp.json` / `.copilot/mcp-config.json`) registers thin adapters for the old 27 names that delegate to the new tools and return the old result shapes. This keeps the footprint reduction opt-out rather than opt-in, while giving custom prompts a one-release grace period. Adapters are removed in 2.0.
- Skills and agents in this repo are updated to the new names in the same release (§4.1 lists the files).
- `omg_check_completion` keeps its name and shape so the always-on instructions and v2 hook design stay stable.
- Deprecation notices are logged to stderr once per session when a legacy adapter is called.

  | `copilot-instructions.md` | 3,594 | 549 |
  | MCP tool definitions | 2,585 (27) | 863 (6) |

- MCP server: `cd mcp-server && npm run build && npm test` — 51 tests, 50 pass; the one failure (`safeReadFile returns null for symlinks`) is pre-existing and environmental (symlink creation needs Developer Mode/admin on Windows). The 28 new tool-surface tests pass, including the `≤ 900` token budget assertion (measured 863 in-process).
- Activation, static: `npm run activation` checks every phrase from the removed keyword table (`evals/fixtures/legacy-keyword-triggers.json`) against the owning skill's description. **Result: 80 phrases, 0 missing** after adding `prd loop`, `story loop` (ralph), `stakeholder interview` (deep-interview), `check secrets`, `audit deps` (security-scan), `cancel omg`, `cancelomc` (cancel). Re-run after Part B: unchanged (skill bodies changed, descriptions did not). The two deprecated bridge skills have no frontmatter and are reported as not natively discoverable.
- Activation, live: `npm run activation:live` runs `evals/fixtures/activation-probes.json` through Copilot CLI (`-p`, mutating tools denied) and asserts on `skill` tool calls. **Result 2026-11-09 (CLI 1.0.107, gpt-6.1-sol): 8/8** — six removed-phrase prompts loaded the expected skill, the control prompt loaded none, and a Korean prompt activated `security-scan` from its English description. See `evals/reports/2026-11-09-activation-live.md`. VS Code and cloud agent activation are still to be checked manually (different surfaces, see hooks/plugins caveats in the v2 plan).
- Init/upgrade: run `OMG: Initialize Workspace` on a fresh workspace and `OMG: Update Convention Files` on a workspace initialised with 1.4.4; confirm the OMG section is replaced in place and user content above the marker is preserved. *(manual check pending.)* Preparing this check exposed a gap: the update command copied `mcp-server/src` but never rebuilt `dist/`, which with the renamed tools would leave an upgraded workspace serving the 27 old tools to skills that call the new ones. Fixed — update now rebuilds the server and offers a window reload — and `mcp-server/package.json` is versioned `1.5.0` so the health check's version-drift comparison (previously `1.0.0` on both sides, so never triggered) flags 1.4.x workspaces.
- Hooks: smoke-run of `pre-tool-use` / `post-tool-use` on Windows PowerShell 5.1, PowerShell 7 and bash (2026-11-11). The checkpoint advisory still names `omg_checkpoint`. Two pre-existing PowerShell defects were found and fixed: the force-push guard missed `--force` / `-f` at the end of the JSON tool input (approved on Windows, denied by the bash hook), and multi-segment `Join-Path` made both hooks fail on Windows PowerShell 5.1 (no decision printed on the default path; context byte counting and the checkpoint trigger never ran). After the fix an 11-case guard table gives identical decisions on all three shells. Turning that table into a CI fixture is tracked in the [threat model](../security/threat-model.md) (T4, T5).

## 6. Deprecations announced in 1.5.0

- `/resume-claude`, `/push-omc` and the `omg_*_external_session` / `omg_compare_checkpoints` tools (OMC bridge). In 1.5 these tools are registered only with `OMG_LEGACY_TOOLS=1`, so the two skills require that flag. Removed in 2.0.
- `omg_select_model`. Registered only with `OMG_LEGACY_TOOLS=1` in 1.5; removed in 2.0 (agents declare `model:` in frontmatter).
- Legacy MCP tool names (25 adapters + lenient `omg_checkpoint` parameters). Available behind `OMG_LEGACY_TOOLS=1` in 1.5.x (set `env` on the server in `.vscode/mcp.json`); the first legacy call per session logs a deprecation notice to stderr. Removed in 2.0.

## 7. Decisions

- Part A and Part B ship together in **1.5.0** (decided 2026-11-09). Both are implemented on this branch.
- `omg_memory` stays in 1.5 (used by `/remember`, `/wiki`, `/writer-memory`); whether native Copilot memory replaces it is a v2 question. The `category` field is kept on disk and defaults to `project` for new entries; the 1.5 tool exposes `tags` instead of a category parameter.
- `omg_check_completion` keeps the 1.4 result shape and gains fields additively (2026-11-10). `allow_stop` still depends only on active mode state — an open PRD story or an active ultragoal is reported (`unverified`, `ultragoal`) but does not block stopping, because ultragoals are durable across sessions by design and a stale PRD must not pin a session forever.
- `omg_write scope:"story"` refuses `passes:true`; the only path to a passing story is `omg_verify` with non-empty, all-passed evidence. The legacy `omg_update_story` adapter keeps its permissive 1.4 semantics for the grace period (explicit opt-in via the env flag).
- Session budget (2026-11-10, user directive): the always-on instructions require handing off at 50% of the context window (checkpoint, commit verified work, self-contained next-session prompt). `omg_checkpoint` returns `handoff_text` to seed that prompt; the hooks' byte-count advisory remains the early-warning tier.
